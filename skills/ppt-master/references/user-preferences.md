# User Preferences (Standing Defaults)

本文件记录用户长期有效的版式偏好。每次用本 skill 生成或修改 PPT 页面时默认遵守：Strategist 在规划字号锚点和页面内容时遵守，Executor 在绘制每一页前遵守。

**优先级**：当次对话里用户的明确要求 > 本文件 > skill 内其他 `Default` / `Reference` 级别的建议。本文件不越过 skill 的 `Hard rule` / `Required` / `Forbidden` 技术约束；两者冲突时，用满足技术约束的写法实现偏好的意图。

---

## 1. 不加没必要的小字批注

页面上只放听众需要、而且听众不知道的信息。以下内容默认不上页面：

- 听众本来就知道的背景信息（例：给学生讲选课时，再列一遍每天的上课节次）。
- 页码交叉引用和导航提示（例：“→ P11”“理由见 P16”“后面一个个回答”）。
- 单独占一行的“情景数据 / 示例数据 / 示意图”说明小字。
- 重复图表已经表达清楚的图例行或注释行。

仍然需要交代的假设、单位、出处，**并入标题、图表标题或正文**（例：“例：体育课三个班怎么挑（示例）”“假设点一门 10 秒，保存 40 秒”），不单独成一行小字；只需要口头补充的内容写进讲稿。

> 与 `executor-base.md` §3 Fact provenance 的关系：情景数据仍须可辨认，但用上面“并入标题或正文”的方式标注，或在讲稿中说明，不另起一行小字标签。

## 2. 字号下限

按 1280×720 画布的 px 计（其他画布按宽度等比换算）：

| 文字类型 | 下限 |
|---|---|
| 正文、卡片正文、要点、流程节点文字 | 22px |
| 说明、标签、图例、出处、图表标签 | 18px |
| 页脚、页码 | 不受上面限制 |

规划 `spec_lock.md typography` 时，正文锚点不低于 22，`annotation` / `label` 等说明类角色不低于 18。放不下时，先精简文字、重新断行或调整版面，不把字号降到下限以下。

## 3. 稀疏页用相关图形填，不靠放大字号

页面显得空时，用和本页内容有关的东西来填：

- 线条、框线、分隔、编绳等结构性线条；
- 相关的图形、图标圈、示意图、矢量插画（例：分隔页列出本部分各页标题，原文写在竹简上；讲抽签时画一个签筒；四个要点各配一个图标）；
- 有信息量的补充（例：本部分包含哪些页、每个要点要回答的问题）。

**不要**用放大字号、拉大行距或间距、把元素撑大的方式填满页面。

## 4. 背景不用纯色，加矢量纹样

除非用户明确要纯色，背景按需求加一层低调的矢量纹样，用来增加质感、填补空隙：

- 纹样跟随 deck 的视觉风格。例：国风 / 中式 deck 用书页双线框、淡墨远山、祥云卷纹；科技风用细网格、几何线；商务风用细线几何、大色块切角。
- 透明度要低（填充约 0.03–0.06，线条约 0.3–0.6），不能干扰正文阅读。
- 实现：在 `bg` 底色矩形之后放一个整页装饰组 `<g id="bg-decor" data-pptx-role="decoration" data-pptx-bounds="0 0 1280 720">`，里面放矢量形状；结构角色组不参与区域重叠检查，也不参与动画。纹样避开标题和正文的主要阅读区。
- 每页可以沿用同一套纹样，保持整套风格统一；封面、分隔页可以加强，内容密集页要减弱。

## 5. 交付：一个文件夹，打开就是 PPT

做完后用 [`deliver`](../workflows/stages/deliver.md) 打包，不把 PPT 留在 `projects/…/exports/` 里：

- 文件夹和 PPT 都用 deck 的中文标题命名，不用项目代号、日期、时间戳这类看不懂的数字字母串。
- 外层只放定稿 `.pptx` 和一个「制作文件」文件夹；里面的子文件夹用直观的中文名，只留以后改 PPT 需要的东西，其余中间产物删掉。用户定稿后可以自己删掉「制作文件」。

## 6. 本机字体全部嵌入 PPT

PPT 里用到的本机字体都嵌入进去，保证在别的电脑上也能正常显示（打包时自动完成）。授权不允许嵌入、或者本机没装的字体，要告诉用户。
